# Map Save Format

Every map/scenario is **one JSON file** that fully defines unit positions and status plus all drawn lines.

| Location | Purpose |
|---|---|
| `Assets/StreamingAssets/Maps/*.json` | Shipped default scenarios (e.g. `lyon_dev.json`) |
| `%USERPROFILE%\AppData\LocalLow\IvanSostarko\Iron Meridian\Maps\*.json` | Player saves (shadow the defaults by file name) |

Save with the HUD **SAVE** button or `F5`; load with **LOAD** / `F9`.

## Schema

```jsonc
{
  "mapName": "Lyon Dev",
  "savedAtUtc": "2026-07-28T00:00:00Z",
  "centerLatitude": 45.7640,          // map/camera centre (WGS84)
  "centerLongitude": 4.8357,
  "cameraHeightMeters": 14000,
  "viewMode": "Mode3D",               // Mode2D | Mode3D
  "showBuildings": true,              // 3D buildings layer (independent of viewMode)

  "units": [
    {
      "instanceId": "blue-inf-1",     // unique per placed unit
      "defId": "infantry",            // id from Data/units.json
      "team": "User",                 // User (Blue) | Enemy (Red)
      "affiliation": "Friendly",      // Friendly | Hostile | Neutral | Unknown
      "echelon": "Battalion",         // Team ... Army
      "customName": "1st Infantry Battalion",
      "latitude": 45.7760, "longitude": 4.8050, "heightMeters": 0,
      "headingDeg": 90,
      "strength": 1.0,                // 0..1
      "organisation": 60, "morale": 65,
      "status": "Idle",               // Idle|Moving|Engaging|Suppressed|Routed|Destroyed
      "ammo": 42000, "fuel": 0, "foodDays": 3
    }
  ],

  "lines": [
    {
      "id": "sector-User-lateral-0",
      // Boundary | DefensiveLine  (legacy)
      // LateralBoundary | RearBoundary | Feba | PhaseLine  (tactical graphics)
      "kind": "LateralBoundary",
      "team": "User",                 // owning side ("" when it separates both)
      "is3D": true,                   // terrain-draped (3D) or flat (2D)
      "autoGenerated": true,          // true = derived, regenerated on demand
      "points": [ { "latitude": 45.82, "longitude": 4.86, "heightMeters": 0 }, ... ],

      // Amplifiers (APP-6A / FM 101-5-1 labelling) — all optional
      "label": "",                    // caption on the line, e.g. "FEBA", "PL BLUE"
      "echelon": "II",                // size marking straddling a boundary
      "leftLabel": "1st Infantry",    // formation either side of a boundary
      "rightLabel": "2nd Armour",
      "planned": false                // true = drawn broken (planned/on-order)
    }
  ]
}
```

All amplifier fields were added after the original schema and default harmlessly
on older saves — `JsonUtility` leaves missing fields at their initialiser values.

### Tactical graphics

`SectorSystem` derives a side's control measures from where its units stand
(left panel → **GENERAL** → *Generate sectors*). Ids are prefixed
`sector-<team>-`, and everything under that prefix is regenerated or cleared as
a set, so hand-drawn lines are never touched.

| Kind | Meaning |
|---|---|
| `LateralBoundary` | Left/right limit of a formation's AO. Runs **rear-to-front** between laterally adjacent formations and extends past the foremost units (the forward boundary). |
| `RearBoundary` | Rear limit of the AO, parallel to the front. Ground behind it belongs to the higher commander. |
| `Feba` | Forward Edge of the Battle Area — the line through the forward combat units, excluding screening forces. This is the "defence line". |
| `PhaseLine` | Named reference line for control and coordination. |

Positions are geodetic (WGS84), so saves are independent of the Unity scene origin and portable between map centres.

## Creating a new scenario

Copy `lyon_dev.json`, change `mapName`, `centerLatitude/Longitude`, edit the `units` array, and point `GameController.mapFileName` at the new file (or extend `TestingUI` with a new card).
