# Architecture

## Design principles

1. **No binary scenes/prefabs in git.** Scenes are generated by `Assets/Editor/ProjectBootstrap.cs`; every screen builds its UI at runtime through `UIFactory`. Diffs stay readable and AI-assist friendly.
2. **Geodetic truth.** Unit and line positions are stored as WGS84 lat/lon; Unity world positions are derived per frame/origin via `GeoUtils` and `CesiumGlobeAnchor`. Saves are portable.
3. **Data-driven units.** All 37 unit types live in `units.json`; code never hard-codes a unit type.

## Flow

```
MainMenu ─▶ Testing ─▶ Game scene
                        GameController.Start()
                          ├─ MapManager.Build(Lyon)          Cesium globe
                          ├─ CameraRig.Init                  strategy camera
                          ├─ LineManager / LineDrawTool / FrontlineSystem
                          ├─ VfxSystem                       fire/smoke (before units spawn)
                          ├─ CombatSystem / SelectionManager
                          ├─ UIFactory canvas ─ GameHUD / UnitPaletteUI / UnitInfoPanel
                          └─ SaveSystem.LoadMap("lyon_dev.json") ─▶ UnitActor.Spawn ×N
```

## Known simplifications (roadmap)

- Combat is deterministic per tick; no terrain modifiers or ZOC yet.
- Enemy AI holds position — only combat reacts.
- Defensive lines are visual; they don't yet grant defence bonuses.
- 2D mode is a top-down camera, not a separate cartographic renderer.
- Movement is straight-line geodesic; no road/pathfinding network.
