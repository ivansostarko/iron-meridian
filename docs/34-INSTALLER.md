# The Windows installer

The player folder Unity produces is 350 MB of loose files with a stock engine
icon and no way back off the disk. The installer turns it into a single `.exe`
(121 MB, compressed) that puts the game somewhere sensible, gives it Start-menu
and desktop shortcuts with the game's own icon, and uninstalls cleanly without
taking the player's saves with it.

Built with **[Inno Setup 6](https://jrsoftware.org/isinfo.php)** — free, adds no
runtime of its own, and the whole setup is one text file that reviews and
diffs like code.

```
installer/
  iron-meridian.iss              the setup script — sections, files, [Code]
  notes.txt                      shown on the last wizard page
  assets/                        generated by scripts/generate_installer_art.py
    iron-meridian.ico            shortcut + setup icon, 16-256 px
    wizard-large-*.bmp           welcome/finished panel, three DPI sizes
    wizard-small-*.bmp           inner-page header strip, three DPI sizes
scripts/
  build-windows.ps1              builds the player (-Installer chains on)
  build-installer.ps1            packages an existing player
  generate_installer_art.py      logo -> .ico + wizard bitmaps
```

`make installer` runs the lot; `docs/35-TASKS.md` is the full job list.

## 1. Building one

```powershell
make installer      # player + installer in one go, from a clean output folder
make package        # or just package a player you already have
```

The scripts behind those two, when you want their options (§2a, §4):

```powershell
.\scripts\build-windows.ps1 -Clean -Installer
.\scripts\build-installer.ps1
```

The result is `Builds\Installer\IronMeridian-<version>-Setup.exe`, and the
script prints its size and SHA-256 — publish the hash with the download.

`build-installer.ps1` works everything out for itself and fails loudly rather
than guessing:

| It needs | Where it gets it | Override |
|---|---|---|
| The player | `Builds\Windows` | `-SourceDir` |
| The `.exe` name | the one `.exe` with a matching `*_Data` folder beside it | — |
| The version | `bundleVersion` in `ProjectSettings.asset` | `-Version` |
| Inno Setup | `%ProgramFiles(x86)%\Inno Setup 6\ISCC.exe`, then `PATH` | `-IsccPath` |
| The artwork | `installer/assets` — regenerated if the `.ico` is missing | — |

Inno Setup itself is the one thing that has to be installed by hand:

```powershell
winget install --id JRSoftware.InnoSetup
```

If two players sit in the same folder (a rename of `productName` leaves the old
one behind), the script packages the newest and says so. Build with `-Clean` to
stop that happening at all.

## 2. What ends up in the package

Everything Unity emitted, minus four things:

- `*_DoNotShip` — Burst's debug symbols, which name themselves
- `*.pdb`, `*.log` — debug and run leftovers
- `cesium-token.txt` — **see below**

Plus `iron-meridian.ico`, because the player carries Unity's default icon
(nothing is set in **Player Settings → Icon**) and a shortcut pointing straight
at the `.exe` would show the engine logo rather than the game.

### 2a. The Cesium ion token

Golden rule 1 says the token never leaves your machine, and an installer is the
easiest way to break that rule by accident: hand someone a setup `.exe` and you
have handed them your token, in plain text, inside a file they can open.

So the token is **excluded by default**. A build packaged this way starts
fine but draws no ground until the player supplies their own token — which
`notes.txt` tells them how to do, on the last page of the wizard.

Pass `-IncludeToken` when you deliberately want it in there (an internal build,
a demo machine, a token scoped to nothing but tile access):

```powershell
.\scripts\build-installer.ps1 -IncludeToken
```

The script prints a warning either way, so which one you built is never a
guess.

## 3. What the wizard does

| | |
|---|---|
| **Privileges** | Per-user by default — no UAC prompt. The first page offers a machine-wide install for anyone who wants one (`PrivilegesRequiredOverridesAllowed=dialog`) |
| **Location** | `{autopf}\Iron Meridian` — Program Files, or the per-user equivalent |
| **Requirements** | 64-bit Windows 10 1809 or newer (`MinVersion=10.0.17763`, `ArchitecturesAllowed=x64compatible`) |
| **VC++ runtime** | Checked before anything is written. Missing it, the player exits silently with nothing in any log, so the wizard warns and links the redistributable rather than letting that happen |
| **Shortcuts** | Start menu always, desktop as a task (ticked by default) |
| **Upgrades** | Same `AppId`, so a newer setup replaces the install in place. A running copy is caught by the Restart Manager and the wizard offers to close it |
| **Finish** | `notes.txt` — the token, where saves live, the first five minutes |

### 3a. Uninstalling

The install folder goes. **The player's files do not, unless they say so** —
saves, custom maps, `missions.json` and `tuning.json` live in Unity's
persistent data folder:

```
%USERPROFILE%\AppData\LocalLow\IvanSostarko\Iron Meridian
```

The uninstaller offers to delete that folder with **No** preselected, so
reinstalling a newer version keeps a campaign in progress. (A machine-wide
install uninstalls with elevation, so the folder it offers to clear is the
elevating account's — the per-user default has no such wrinkle.)

### 3b. Unattended

Both halves run without a user, which is what makes them usable from a
deployment script or a test:

```powershell
IronMeridian-1.0-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DIR="C:\Games\Iron Meridian" /TASKS=desktopicon
"C:\Games\Iron Meridian\unins000.exe" /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

Suppressed, the two questions the wizard can ask answer themselves the safe
way: the VC++ warning continues, and the uninstaller **keeps** the save folder.
`/TASKS=` with nothing after it installs no desktop icon.

## 4. Signing

Unsigned, SmartScreen will warn on first download. With a code-signing
certificate, pass the command through and both the setup and the uninstaller
are signed (`SignedUninstaller=yes`):

```powershell
.\scripts\build-installer.ps1 -SignToolCommand 'signtool.exe sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 /a $f'
```

`$f` is Inno's placeholder for the file being signed — leave it as-is.

## 5. The artwork

Regenerate after touching the logo:

```powershell
python scripts/generate_installer_art.py     # needs Pillow
```

It trims `Assets/Resources/Graphics/Logo/game-logo.png`, centres it on
`UiTheme.AppBackground` with a wash of `UiTheme.Accent`, and writes three sizes
each of the two wizard bitmaps (Inno picks by DPI).

The `.ico` gets **only the emblem**, not the whole logo. The full lockup is
close to 3:1 and at 16 px — the size Windows uses in a taskbar or a file list —
a wordmark that wide is a smudge. The script finds the empty gutter between the
mark and the type and cuts there, so the icon is the shield alone at every size.
A logo with no such gutter falls back to being used whole.

Nothing in `installer/assets` is hand-edited — change the logo or the script,
never the output.

## 6. Changing the setup

Everything lives in `installer/iron-meridian.iss`. Three things to know before
editing:

- **Never change `AppId`.** It is how Windows recognises an existing install.
  A new GUID means the next setup installs a second copy alongside the first
  instead of upgrading it, and the old one's uninstaller stays in the control
  panel pointing at files that are gone.
- The `[Code]` section is Pascal, where `{ ... }` is a comment — so a comment
  containing `{app}` silently ends early and the compile fails somewhere later
  with a syntax error. Write install-folder in prose, not as a constant.
- **Ask questions with `SuppressibleMsgBox`, never `MsgBox`.** A plain `MsgBox`
  is shown even under `/VERYSILENT /SUPPRESSMSGBOXES`, so an unattended run
  stops dead on a dialog no one can see, having already moved the files.
  `SuppressibleMsgBox` takes the answer to assume as its last argument — pick
  the harmless one (§3b).

To check a change without waiting on a 350 MB compress, point it at a stub:

```powershell
New-Item -ItemType Directory -Force stub\IronMeridian_Data | Out-Null
New-Item -ItemType File -Force stub\IronMeridian.exe, stub\IronMeridian_Data\d.bin | Out-Null
.\scripts\build-installer.ps1 -SourceDir stub -OutputDir stub-out -Version 0.0-test
```

That compiles in about three seconds and still exercises every section,
including `[Code]`. A silent install and uninstall of the result into a throwaway
folder (§3b) is worth doing after any change to the `[Code]` section.

## 7. CI

`build-installer.ps1` needs only ISCC and a player folder, so it runs as a step
after [game-ci/unity-builder](https://game.ci/) on a Windows runner:

```yaml
- run: choco install innosetup -y
- run: .\scripts\build-installer.ps1 -SourceDir build\StandaloneWindows64 -Version ${{ github.ref_name }}
```

Don't feed a repository secret through `-IncludeToken` on a public release job
— the artifact is downloadable, and §2a applies just as much to a robot.
