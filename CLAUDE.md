# CLAUDE.md — Iron Meridian

Guidance for Claude Code (and other AI assistants) working in this repository.

## What this project is

Unity 6 (6000.0 LTS) real-terrain operational wargame using **Cesium for Unity 1.24** (scoped registry `https://unity.pkg.cesium.com`). Two teams — User (Blue) and Enemy (Red) — deploy APP-6-iconed units on Cesium 3D terrain (default: Lyon), draw boundaries/defensive lines, and fight tick-based battles that automatically reshape the front line.

## Golden rules

1. **Never commit a Cesium ion token.** Token lives in `Assets/StreamingAssets/cesium-token.txt` (git-ignored) or the `CesiumTokenConfig.IonAccessToken` constant (placeholder only in git). See `docs/02-CESIUM.md`.
2. **No binary scenes or prefabs.** Scenes are generated by `Assets/Editor/ProjectBootstrap.cs`; all UI is built at runtime via `Assets/Scripts/UI/UIFactory.cs`. If a screen changes, change its `*UI.cs` builder.
3. **Units are data.** Never hard-code unit stats in C#. Edit `scripts/generate_units.py` → run it → `Assets/StreamingAssets/Data/units.json`. Icons: `scripts/generate_icons.py` (Python + Pillow) → `Assets/Resources/Icons/`.
4. **Positions are geodetic.** Store lat/lon (WGS84) in state/saves; convert with `GeoUtils`. Don't persist Unity world coordinates.
5. **Legacy input & built-in render pipeline.** Uses `UnityEngine.Input` and uGUI with legacy `Text` — do not introduce the new Input System or TextMeshPro without being asked.
6. Keep namespaces `IronMeridian.*` matching folder layout.
7. **Loading screens go through `LoadingScreenUI`.** Every loader needs a guaranteed dismissal path — a completion test *and* a timeout *and* explicit dismissal on error; a loader that can trap the player is worse than none. It gets its own canvas (sorting order 500), a bar that never moves backwards, and unscaled time. **`docs/12-LOADERS.md` is the register of every loader — update it in the same change whenever you add, remove or repurpose one, or use new artwork in one.**
8. **Screen backgrounds go through `UIFactory.CreateScreenBackground` / `BackgroundCatalog`.** Images live under `Assets/Resources/`; never hand-roll a full-screen `Image` or stretch artwork (aspect is preserved by envelope-fitting). Scrim levels live in the catalogue, not at call sites. **`docs/11-GAME-MENU.md` is the register of every background image — update it in the same change whenever you add, replace or remove one, or use one on a new screen, recording its path, screens and description.**
9. **Audio goes through `MusicManager` / `AudioCatalog`.** Audio files must live under `Assets/Resources/` (nothing else is loadable at runtime). Background music is a `DontDestroyOnLoad` singleton — never add a per-scene `AudioSource` for it, or the track restarts on every navigation. Levels live in `AudioCatalog`, not at call sites. **`docs/10-AUDIO.md` is the register of every sound — update it in the same change whenever you add, replace or remove an audio asset, or play one on a new screen, recording its path, screens and description.**
10. **3D models go through `UnitModelLibrary`.** Never `Resources.Load` a model prefab at a call site. Model prefabs in `Assets/Resources/Models/` are generated by **Tools → Iron Meridian → Install Unit Models** — don't hand-edit them. Animation is **legacy `Animation`**, not Mecanim: there is no Animator Controller asset and none can be made at runtime. **`docs/09-3D-MODELS.md` is the register of every model and where it's shown — update it in the same change whenever you add, replace or reassign a 3D model, add an animation clip, or display a model somewhere new.**
11. **Particle effects go through `VfxSystem`.** Never build a `ParticleSystem` in gameplay code; add a `VfxId` + catalogue row in `Assets/Scripts/Vfx/VfxCatalog.cs` and call `VfxSystem.Play`/`Attach`. Every authored effect needs a procedural fallback (asset packs must be removable). **`docs/08-PARTICLE-SYSTEMS.md` is the register of every effect and every call site — update it in the same change whenever you add, remove or repurpose a particle effect, or add a new place one is triggered.**

## Common tasks

| Task | How |
|---|---|
| Add a unit type | `.claude/commands/add-unit.md` — units.json entry + icon glyph + regenerate |
| Regenerate icons | `python scripts/generate_icons.py` (needs Pillow) |
| Add a scenario map | Copy `Assets/StreamingAssets/Maps/lyon_dev.json`, edit; see `docs/05-MAP-SAVES.md` |
| Windows build | `scripts/build-windows.ps1` or `docs/06-WINDOWS-BUILD.md` |
| New screen | Create `Assets/Scripts/UI/<Name>UI.cs` runtime builder + scene entry in `ProjectBootstrap` + `GameConfig` scene name |
| Add a particle effect | `VfxId` + catalogue row in `VfxCatalog.cs` → fallback in `ProceduralVfx.cs` → call via `VfxSystem` → **update `docs/08-PARTICLE-SYSTEMS.md`** |
| Install authored VFX prefabs | **Tools → Iron Meridian → Install VFX Prefabs** (copies them into `Assets/Resources/VFX/`) |
| Add a 3D model | Entry in `UnitModelLibrary.cs` → register FBXs in `ModelInstaller.cs` → **Tools → Iron Meridian → Install Unit Models** → **update `docs/09-3D-MODELS.md`** |
| Add audio | File under `Assets/Resources/Audio/` → row in `AudioCatalog.cs` → play via `MusicManager` → **update `docs/10-AUDIO.md`** |
| Add a screen background | Image under `Assets/Resources/Backgrounds/` → row in `BackgroundCatalog.cs` → `UIFactory.CreateScreenBackground` → **update `docs/11-GAME-MENU.md`** |
| Add a loader | `LoadingScreenUI.Show(...)` + `Track(progress, isComplete)` → block the screen's input guards → **update `docs/12-LOADERS.md`** |
| Add an offensive task | `AttackTask` value in `Enums.cs` → row in `AttackTaskCatalog.cs` → **update `docs/15-COMBAT-ORDERS.md`** (the submenu and the order loop are both driven by the catalogue) |
| Add a recon task | `ReconTask` value in `Enums.cs` → row in `ReconTaskCatalog.cs` → **update `docs/16-FOG-OF-WAR.md`** |

## Verification

There is no test suite yet. After code changes: open in Unity 6, ensure console is clean, run **Tools → Iron Meridian → Setup Project**, Play → Testing → Dev, and check: map loads (with token), palette drag-drop works, LMB/RMB unit orders work, lines draw, battle runs, F5/F9 save-load round-trips.
