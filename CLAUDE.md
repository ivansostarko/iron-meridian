# CLAUDE.md — Iron Meridian

Guidance for Claude Code (and other AI assistants) working in this repository.

## What this project is

Unity 6 (6000.0 LTS) real-terrain operational wargame using **Cesium for Unity 1.25** (scoped registry `https://unity.pkg.cesium.com`). Two sides — User (Blue) and Enemy (Red) — deploy APP-6-iconed units on Cesium 3D terrain (default: Lyon), call strikes on them, and fight tick-based battles that automatically reshape the front line. Control measures are **derived**, not drawn by hand: the front line, generated sector boundaries and the lines a DEFEND/HOLD/GUARD order puts down.

## Golden rules

1. **Never commit or ship a Cesium ion token.** Token lives in `Assets/StreamingAssets/cesium-token.txt` (git-ignored) or the `CesiumTokenConfig.IonAccessToken` constant (placeholder only in git). See `docs/02-CESIUM.md`. A player build copies it into `StreamingAssets`, so the installer strips it back out unless `-IncludeToken` is passed on purpose — `docs/34-INSTALLER.md` §2a. **Neither the Android nor the web build has such a strip**: an APK carries the token in plain text (`docs/40-ANDROID.md` §6), and a WebGL build **serves it as a fetchable file to anyone who loads the page** — `docs/41-WEB.md` §6.
2. **No binary scenes or prefabs.** Scenes are generated by `Assets/Editor/ProjectBootstrap.cs`; all UI is built at runtime via `Assets/Scripts/UI/UIFactory.cs`. If a screen changes, change its `*UI.cs` builder.
3. **Units are data.** Never hard-code unit stats in C#. Edit `scripts/generate_units.py` → run it → `Assets/StreamingAssets/Data/units.json`. Icons: `scripts/generate_icons.py` (Python + Pillow) → `Assets/Resources/Icons/`. In-game tuning (**Development → Units List**) writes a *sparse patch* to `tuning.json` in the save folder, applied on top of the generated file and the weapon catalogues — see `Save/TuningStore.cs`. Regenerating `units.json` never discards it; that is the point of the split.
4. **Positions are geodetic.** Store lat/lon (WGS84) in state/saves; convert with `GeoUtils`. Don't persist Unity world coordinates.
5. **Legacy input & built-in render pipeline.** Uses `UnityEngine.Input` and uGUI with legacy `Text` — do not introduce the new Input System or TextMeshPro without being asked. Anything the mouse and keyboard have no equivalent for goes through a translation layer rather than into the call sites: **`Core/TouchInput.cs`** for gestures (**`docs/40-ANDROID.md` §2**) and **`Core/GamepadInput.cs`** for the pad (**`docs/42-STEAM-DECK.md` §3**).
6. Keep namespaces `IronMeridian.*` matching folder layout.
7. **Loading screens go through `LoadingScreenUI`.** Every loader needs a guaranteed dismissal path — a completion test *and* a timeout *and* explicit dismissal on error; a loader that can trap the player is worse than none. It gets its own canvas (sorting order 500), a bar that never moves backwards, and unscaled time. **`docs/12-LOADERS.md` is the register of every loader — update it in the same change whenever you add, remove or repurpose one, or use new artwork in one.**
8. **Screen backgrounds go through `UIFactory.CreateScreenBackground` / `BackgroundCatalog`.** Images live under `Assets/Resources/`; never hand-roll a full-screen `Image` or stretch artwork (aspect is preserved by envelope-fitting). Scrim levels live in the catalogue, not at call sites. **`docs/11-GAME-MENU.md` is the register of every background image — update it in the same change whenever you add, replace or remove one, or use one on a new screen, recording its path, screens and description.**
9. **Audio goes through `MusicManager` / `AudioCatalog`.** Audio files must live under `Assets/Resources/` (nothing else is loadable at runtime). Background music is a `DontDestroyOnLoad` singleton — never add a per-scene `AudioSource` for it, or the track restarts on every navigation. Levels live in `AudioCatalog`, not at call sites. **`docs/10-AUDIO.md` is the register of every sound — update it in the same change whenever you add, replace or remove an audio asset, or play one on a new screen, recording its path, screens and description.**
10. **3D models go through `UnitModelLibrary`.** Never `Resources.Load` a model prefab at a call site. Model prefabs in `Assets/Resources/Models/` are generated by **Tools → Iron Meridian → Install Unit Models** — don't hand-edit them. Animation is **legacy `Animation`**, not Mecanim: there is no Animator Controller asset and none can be made at runtime. **`docs/09-3D-MODELS.md` is the register of every model and where it's shown — update it in the same change whenever you add, replace or reassign a 3D model, add an animation clip, or display a model somewhere new.**
11. **Particle effects go through `VfxSystem`.** Never build a `ParticleSystem` in gameplay code; add a `VfxId` + catalogue row in `Assets/Scripts/Vfx/VfxCatalog.cs` and call `VfxSystem.Play`/`Attach`. Every authored effect needs a procedural fallback (asset packs must be removable). **`docs/08-PARTICLE-SYSTEMS.md` is the register of every effect and every call site — update it in the same change whenever you add, remove or repurpose a particle effect, or add a new place one is triggered.**

## Common tasks

| Task | How |
|---|---|
| Anything routine | `make` lists every job (`make build`, `make installer`, `make data`, `make doctor` …). No make installed? `.\scripts\menu.ps1` is the same menu with a picker. Job table lives in `scripts/menu.ps1` — **`docs/35-TASKS.md`** |
| Edit a `scripts/*.ps1` | Save it **UTF-8 with BOM**. Windows PowerShell reads a BOM-less file as ANSI, and a mangled em dash ends in a smart quote it treats as a string delimiter — one `—` inside one string breaks the whole file. `docs/35-TASKS.md` §3 |
| Add a Unity package | Have a use for it first, check what it drags in (`Packages/packages-lock.json`, `depth` > 0) and whether it runs anything at startup → row in **`docs/38-PACKAGES.md`** in the same change. `make steam-check` flags packages nothing references |
| Add a unit type | `.claude/commands/add-unit.md` — units.json entry + icon glyph + regenerate |
| Change the names units get on the map | Edit `Assets/StreamingAssets/Data/unit-names.json` — hand-maintained, nothing generates it. Titles are matched to a type by `unitIds` then `branches`; a title carries no echelon. **`docs/04-UNITS.md` § Formation names** |
| Regenerate icons | `make icons` — or `python scripts/generate_icons.py` (needs Pillow) |
| Take a screenshot / record footage | Map editor → left rail → **CAPTURE**. Files land in `Pictures/Iron Meridian`. Recording writes an H.264 `.mp4` via **ffmpeg as a child process** — Unity has no runtime encoder, so the RECORD button is disabled until ffmpeg is on PATH (`winget install --id Gyan.FFmpeg`). Bundling ffmpeg carries its licence into the release — `docs/39-CAPTURE.md` §2b. `Core/CaptureSystem.cs` |
| Fly a camera path over a battle | Battle mode → left rail → **CINEMA MODE** → frame a shot, ADD WAYPOINT, repeat, PLAY. `Map/CinemaSystem.cs` — runtime only, never saved. **`docs/03-GAMEPLAY.md` § Cinema mode** |
| Add a scenario map | Copy `Assets/StreamingAssets/Maps/lyon_dev.json`, edit; see `docs/05-MAP-SAVES.md` |
| Windows build | `make build` — or `scripts/build-windows.ps1`, `docs/06-WINDOWS-BUILD.md` |
| Android build | `make android` (APK) · `make android-aab` (Play) · `make android-install` (onto a device). Needs Android Build Support in the Hub — `make doctor` says. **`docs/40-ANDROID.md`** |
| Read a shipped data file | `Core/StreamingAssetsFile.ReadAllText("Data/x.json")` — **never `File.ReadAllText` on `Application.streamingAssetsPath`**. On Android that path is a URL into the APK and on the web it is a URL on the server; `System.IO` opens neither. **Add the file to `StreamingAssetsFile.CoreFiles`** or the web build cannot preload it. `docs/40-ANDROID.md` §1a · `docs/41-WEB.md` §1 |
| Write under `persistentDataPath` | Call `Core.WebStorage.Flush()` after the write. In a browser the file is only in memory until it is flushed to IndexedDB, and closing a tab is not quitting. `docs/41-WEB.md` §2 |
| Web build | `make web` · `make web-serve` (build + localhost) · `make serve`. Needs WebGL Build Support in the Hub. **A WebGL build cannot be opened with `file://`.** `docs/41-WEB.md` |
| Steam Deck / Linux build | `make linux`. A Deck also runs the Windows build under Proton — `docs/42-STEAM-DECK.md` §2 says which to ship. Upload with `steam-upload.ps1 -Platform Linux` |
| iOS build | `make ios` — **exports an Xcode project, not an app**; the archive and signing need a Mac. `docs/43-IOS.md` §5 |
| Add an Info.plist key | `IosBuild.OnPostprocessBuild`, **never by hand in Xcode** — the project is regenerated on every export and the edit is silently lost. `docs/43-IOS.md` §6 |
| Add a keyboard shortcut | Give it a pad equivalent through `Core/GamepadInput.cs` in the same change. **A Steam Deck has no keyboard**, so a key-only verb does not exist there. `docs/42-STEAM-DECK.md` §3 |
| Add a shipped scenario | Drop the .json in `Assets/StreamingAssets/Maps/`, then run `make setup` — it rewrites `Maps/index.json`, which is the only way Android can list them. `docs/40-ANDROID.md` §1b |
| Anything Steam | `make steam-check` (preflight) · integration is `Assets/Scripts/Core/SteamIntegration.cs`, behind the `IRONMERIDIAN_STEAM` define so the project builds without the SDK · depot templates in `steam/` · upload is `scripts/steam-upload.ps1`, which **requires an explicit `-Token Include`/`-Exclude`**. **`docs/36-STEAM.md`** |
| Verify a code change | `make check` — compiles every runtime `.cs` with Roslyn against Unity's reference assemblies, no editor needed. Not a substitute for opening Unity, but it catches every compile error in seconds. `docs/35-TASKS.md` |
| Windows installer | `make installer` — or `scripts/build-windows.ps1 -Clean -Installer` (or `scripts/build-installer.ps1` on an existing player) → `Builds/Installer/`. Inno Setup script in `installer/iron-meridian.iss`; **the ion token is left out unless `-IncludeToken`**. `docs/34-INSTALLER.md` |
| Change the installer's artwork | `python scripts/generate_installer_art.py` (derives the .ico and wizard bitmaps from the game logo — never hand-edit `installer/assets/`) |
| New screen | Create `Assets/Scripts/UI/<Name>UI.cs` runtime builder + scene entry in `ProjectBootstrap` + `GameConfig` scene name |
| Inspect an effect / a sound / a unit / a film / a model | **Development** → MAP EDITOR · UNITS LIST · PARTICLES · AUDIO · VIDEOS · 3D MODELS. Every lab is driven from a catalogue, so a new row appears without touching the screen |
| Add a particle effect | `VfxId` + catalogue row in `VfxCatalog.cs` → fallback in `ProceduralVfx.cs` → call via `VfxSystem` → **update `docs/08-PARTICLE-SYSTEMS.md`** |
| Install authored VFX prefabs | **Tools → Iron Meridian → Install VFX Prefabs** (copies them into `Assets/Resources/VFX/`) |
| Add a 3D model | Entry in `UnitModelLibrary.cs` → register FBXs in `ModelInstaller.cs` → **Tools → Iron Meridian → Install Unit Models** → **update `docs/09-3D-MODELS.md`** |
| Add audio | File under `Assets/Resources/Audio/` → row in `AudioCatalog.cs` → play via `MusicManager` → **update `docs/10-AUDIO.md`** |
| Add a video | File under `Assets/Resources/Videos/` → `VideoId` + row in `VideoCatalog.cs` → play through the id → **update `docs/32-VIDEO.md`** |

| Add a loader | `LoadingScreenUI.Show(...)` + `Track(progress, isComplete)` → block the screen's input guards → **update `docs/12-LOADERS.md`** |
| Add an order-bar task | Enum value in `Enums.cs` → row in the matching catalogue (`MoveTaskCatalog` / `AttackTaskCatalog` / `ReconTaskCatalog`) → name a `TaskAreaShape` if it is placed → **update `docs/15-COMBAT-ORDERS.md`**. The submenu and the order loop are both driven by the catalogue |
| Draw a task's ground | `TaskAreaSystem.Show` — ring, line or quadrants, with labels, motes and the select pulse. Never build the graphic at the call site. **`docs/15-COMBAT-ORDERS.md` §1a** |
| Add an artillery nature | `ArtilleryCaliber` value + row in `ArtilleryCatalog.cs` → burst/smoke `VfxId` + rows in `VfxCatalog.cs` → `EffectSound` + synth in `ProceduralAudio.cs` → button glyph in `UiIcons.cs` → **update `docs/17-ARTILLERY.md`, `docs/08-PARTICLE-SYSTEMS.md` and `docs/10-AUDIO.md`** |
| Add a mission | Map editor → **MISSIONS** panel (first row in the rail) → NEW MISSION HERE → lay it out → SAVE MISSION + MAP. ## Verification

There is no test suite yet. After code changes: open in Unity 6, ensure console is clean, run **Tools → Iron Meridian → Setup Project**, Play → Development → Map Editor, and check: map loads (with token), palette drag-drop works, LMB/RMB unit orders work, lines draw, battle runs, F5/F9 save-load round-trips. Also walk Development → Units List / Particle Effects / Audio: each must list its catalogue and the console must stay clean.
