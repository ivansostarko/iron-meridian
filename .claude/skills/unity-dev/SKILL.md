# Unity development in Iron Meridian

## Non-negotiables

- Unity **6000.0 LTS**, built-in render pipeline, **legacy Input** (`UnityEngine.Input`), uGUI with legacy `Text`. Do not add Input System, TMP, URP or DOTS without explicit request.
- **No .unity/.prefab edits** — scenes are generated by `Assets/Editor/ProjectBootstrap.cs`. UI changes go into the runtime builders (`Assets/Scripts/UI/*UI.cs` using `UIFactory`).
- Namespaces mirror folders: `IronMeridian.Core`, `.Data`, `.UI`, `.Map`, `.Units`, `.Lines`, `.Save`, `.Audio`, `.EditorTools`.

## Patterns to follow

- New screen: `GameConfig.Scene<Name>` constant → `<Name>UI.cs` runtime builder → `MakeScene(...)` entry in `ProjectBootstrap.SetupProject` → navigation button.
- New game system: MonoBehaviour added and wired in `GameController.Start()`; communicate through events (`UnitRegistry.Changed`, `CombatSystem.RunningChanged`) rather than polling other systems.
- World-anchored objects need `CesiumGlobeAnchor`; set `longitudeLatitudeHeight` (note the order: lon, lat, height). Convert with `GeoUtils`, never hand-rolled math.
- Terrain interaction = physics raycasts (Cesium physics meshes are enabled). Guard against tiles not yet streamed (raycast miss ⇒ user-visible message, not exception).
- Stacked text in a panel row: use `UIFactory.CreateStackedLabels` or `UIFactory.PlaceTopLeft`, never `Place` with a centre anchor and a few pixels of offset — two ~16 px rects around the same midpoint overlap, and the text collides on screen whatever its alignment. Wrap any label that can hold variable-length content in `UIFactory.Fit` so it shrinks instead of running into its neighbour. Side-by-side label/value pairs must share one seam value so their rects meet rather than overlap.
- Loading screens: `LoadingScreenUI.Show(...)` then `Track(progress01, isComplete, timeout)`. It builds its own canvas at sorting order 500 (so it can be created before the screen's UI and still draw on top). Must always dismiss — completion **and** timeout **and** explicit dismissal on error events. Feed the loading flag into the screen's own input guards; `blocksRaycasts` doesn't stop code reading `UnityEngine.Input`. **Update `docs/12-LOADERS.md` (§2 artwork, §3 register) in the same change.**
- Screen backgrounds: one call, `UIFactory.CreateScreenBackground(canvas.transform, BackgroundId.X)`, added to the canvas first so it renders behind. Images live under `Assets/Resources/Backgrounds/`; scrim levels in `BackgroundCatalog.cs`. Never stretch artwork — the builder envelope-fits to preserve aspect. **Update `docs/11-GAME-MENU.md` (§2 register, §3 coverage) in the same change.**
- Audio: files must live under `Assets/Resources/` (only runtime lookup path). Music goes through `Audio/MusicManager.cs` — a `DontDestroyOnLoad` singleton, so a repeat `Play` of the current track is a no-op and the bed survives scene loads; never add a per-scene `AudioSource` for music. Levels/loop flags live in `AudioCatalog.cs`. Fades use `Time.unscaledDeltaTime` (the pause menu zeroes `timeScale`). **Update `docs/10-AUDIO.md` (§2 register, §3 coverage) in the same change.**
- 3D models: resolve through `Models/UnitModelLibrary.cs`, never `Resources.Load` a model at a call site. Prefabs in `Resources/Models/` are generated by `ModelInstaller` (Tools > Iron Meridian > Install Unit Models); animation is legacy `Animation` (no Animator Controller exists or can be created at runtime). Models render into uGUI via `ModelPreview` (RenderTexture + parked camera rig). **Update `docs/09-3D-MODELS.md` (§1 register, §3 usage) in the same change.**
- Particle effects: never build a `ParticleSystem` in gameplay code. Add a `VfxId` + catalogue row in `Vfx/VfxCatalog.cs`, a fallback in `ProceduralVfx.cs`, and call `VfxSystem.Play`/`Attach`. Author fallbacks at ~1 world unit — `VfxSystem` scales to map metres. Throttle anything a combat tick can trigger. **Update `docs/08-PARTICLE-SYSTEMS.md` (§2 catalogue and §3 usage) in the same change** — it is the register of every effect and call site.

## Verifying

No automated tests. Sanity chain: clean console on import → `Tools > Iron Meridian > Setup Project` → Play → Development → Map Editor → drag-drop a unit, LMB/RMB orders, draw a line, toggle 2D/3D, START BATTLE, F5/F9. Any change to save schema must load `lyon_dev.json` without errors (JsonUtility silently defaults missing fields — check values, not just absence of errors).
